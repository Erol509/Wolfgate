# UploadCache

Files the server makes at runtime and shares with clients (Symphony's lobby music and backgrounds) are kept on the
client's disk, so a player downloads each one once instead of on every join.

They used to go through the engine's uploaded-resources channel, which pushes every file to every player as they join
and keeps them only in memory. That channel is client engine code, and Wolfgate's client stays stock, so this module
does the same job in content:

- `WFUploadCacheSystem` (server) mounts shared files under `/Uploaded` for the server's own resource manager and sends
  each client the list (path, Blake2b hash, size) when it joins the lobby and whenever the list changes. It sends only
  the files a client asks for, on the engine's transfer channel (the fast websocket channel when it is up).
- `WFUploadCacheManager` (client, one per process) mounts its own root under `/Uploaded`, takes each file from memory
  or from `UserData/wolfgate/upload_cache/<hash>` when it has it, asks for the rest, checks the hash of what arrives
  and writes it to disk. Files the server stops listing are unmounted and deleted from the cache, so the cache stays the
  size of what the server shares.

Paths stay `/Uploaded/...`, so the lobby's existing wait for late files keeps working. Admin file uploads still use the
engine's channel.
