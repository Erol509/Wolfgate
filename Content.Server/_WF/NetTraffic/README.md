# NetTraffic

Cuts what the server sends during big fights. Everything here is server-side cutting plus a client half that draws what
is no longer sent; the client engine stays stock.

- **Ship shells** (`WFNetShellSystem`): an unguided shell with `ShipWeaponProjectile` goes on a visibility layer no eye
  has, so PVS never sends it. Players near its flight get one batched message when it is fired, one if its course
  changes (a deflector, a bounce) and one when it ends; their client flies a sprite-only copy in a straight line.
  Guided and homing rounds are sent as before. `wf.net.shells`, `wf.net.shell_margin`.
- **Explosions** (`WFNetExplosionSystem`): the visuals entity stays unsent in nullspace instead of going to every
  player on the map. Players within `wf.net.explosion_range` (plus a tile per iteration) get one message with the
  overlay data and the sound they would have heard; the client builds the overlay and steps it a tick at a time.
  `wf.net.explosions`.
- **Structure damage** (`WFDamageNetSystem`, shared): a non-mob's damage is sent at most once per
  `wf.net.structure_damage_interval` seconds while it keeps being hit. The server's damage is never held back, only
  the network update.

- **Grids by system** (`WFMapScopedPvsSystem`): instead of every grid going to every player, a player gets those of
  the systems they look at (a map, or every map of one z-level stack) through their body, the entity their eye follows
  and any camera they watch. Leaving a system deletes its grids on the client; entering one sends them as a join does.
  Maps still go to everyone, since the FTL map lists the maps the client has. Planet worlds, z-transit maps and culled
  asteroid rocks keep their own sending. `wf.net.map_scoped_grids`; the test pool runs with it off.
- **UI states** (`WFUiStateTrimSystem`): the engine sends every UI state stored on an entity to each player who can see
  it, and all of them again when one changes, whether or not a window is open. Radar consoles (every cyborg and gunnery
  console has one), shuttle consoles, gas canisters, holopads and AME controllers now only hold a state while someone
  has the window open; the state is set as it opens. The cyborg's own window (marked `Cyborgs` in `BorgSystem`) is only
  refreshed while open and only when its whole-percent charge changes.
- **Repair snapshots** (`WFRepairDataNetSystem`): a ship's `ShipRepairData` (every tile and fixture, several times the
  size of the grid) is only sent to players who hold or wear a repair tool. Picking one up sends the snapshots the
  player was not given before. `wf.net.repair_data_tool_only`.
- **More closed windows**: lathes, signal timers, camera monitors and ChemMasters only set a UI state while their
  window is open; each already set one as it opens.
- **Per-tick resends**: a solid-fuel generator only touches its fuel storage when a whole unit burns; solution heaters
  heat in half-second steps (`SolutionHeaterSystem.NetTraffic`); decal chunk updates gather for 3 ticks before going
  out (`DecalSystem.NetTraffic`).
- **Broadcasts**: encounter markers, world-forming progress and faction counts go out on change, with the current
  state for players who join later; instrument notes and beam visuals only go to players near enough to have the
  entity.

Ops can measure the effect with the Lupine `netstats` command (`netstats start 60`, report in the log), which breaks
sent bytes down by message, network event, component and prototype.
