# JoinProgress

Shows players what the client is doing while it joins a server, on the launcher connect screen. The engine's own state
reads "Connected" as soon as login succeeds, and everything slow happens after that.

The screen is an old ship terminal, a CRT console in `JoinConsoleStyle`, `JoinConsoleCrt` and `JoinConsoleHazard` over the
usual parallax and moproach. It shows each step (1 of 4) with its elapsed time, a log and, when the files come over the
game connection, a download bar with size and speed. If step 2 takes over 15 s it warns that a firewall or antivirus is probably blocking the file
connection and offers Reconnect. Copy Details puts the timings on the clipboard for a bug report, and the existing copy
buttons on the failed and disconnected pages add them too.

| Step | From | To |
|---|---|---|
| Connecting | `ClientConnectState` leaves `NotConnecting` | it reaches `Connected` (login done) |
| Handshake | `Connected` state | `INetManager.Connected` (string table, serializer, transfer channel) |
| Downloading | `INetManager.Connected` | run level `Connected` (uploaded files, then session setup) |
| Entering the game | run level `Connected` | `LauncherConnecting.Shutdown()`; a rejoining player skips the lobby |

`JoinProgressManager` (server) sends `MsgJoinDownloadInfo` on connect when uploaded files exist. The client's manager
stores it, and it may be late or missing, so the bar only shows once it has arrived. With `transfer.http` on, file bytes
go over the WebSocket and net statistics can't see them, so the message says so and the screen shows elapsed time only.

The warning makes the hang visible; it doesn't remove it. That takes a fallback to the game connection in the engine.
