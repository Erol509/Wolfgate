# DoomArcade

Freedoom and Freedoom Phase 2, played from an arcade cabinet (`WFDoomArcade`, `WFFreedoom2Arcade`) or the PDA Gamehub. It opens a window running a Doom engine on
the player's own client, so nobody else sees the screen. See the GameHub module for its download, the sound nearby
players hear, the leaderboard and prizes.

`Engine/` is [ManagedDoom](https://github.com/sinshu/managed-doom) (GPL-2.0-or-later, see `Engine/LICENSE.txt`) without
its window, audio and file backends. `SandboxShims.cs` stands in for the APIs the client sandbox forbids; save games go
to the player's user data, one folder per game, so they outlive the round and the client. `DoomArcadeSession` drives the engine and
`DoomArcadeScreen` draws it and takes the keyboard while focused. Keyboard only: Ctrl fires.

`DoomArcadeSound` plays the WAD's effects. Content can't stream audio, so `DoomArcadeMusic` renders each MIDI track to a
looping sound on a worker thread with `MeltySynth/` ([MeltySynth](https://github.com/sinshu/meltysynth), MIT); music
starts a moment after a level does. Both follow the game's menu volumes and the player's interface volume.

The downloaded game data is `freedoom1.wad` and `freedoom2.wad` in `Resources/GameData/_WF/DoomArcade` (Freedoom 0.13.0, BSD-3-Clause). Every
client ships `Resources/Textures/_WF/DoomArcade`: `TimGM6mb.sf2` (GPL-2.0, see `TimGM6mb-LICENSE.txt`) and
`freedoom1-noise.wad` and `freedoom2-noise.wad`, each WAD's sounds and music for nearby players, built by `Tools/_WF/DoomArcade/make_noise_pack.py`.
